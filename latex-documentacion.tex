\section{Introducción}

\textbf{Advance Trading} es una plataforma web para comprar y vender criptomonedas (Bitcoin, Ethereum, Binance Coin, Solana) utilizando pesos colombianos a través de MercadoPago (PSE, Efecty, Baloto, tarjetas bancarias). Incluye seguridad de doble factor (2FA), cifrado AES-256, un asistente interactivo 3D (AdvanceBot), y un sistema completo de monitoreo con métricas, logs y trazas distribuidas.

\subsection{¿Qué permite hacer la plataforma?}

\begin{itemize}
    \item Registrarse con correo electrónico y verificación por código
    \item Depositar dinero en COP mediante MercadoPago
    \item Comprar y vender criptomonedas (BTC, ETH, BNB, SOL)
    \item Retirar dinero a cuentas bancarias colombianas
    \item Visualizar un robot animado (AdvanceBot) que guía al usuario
    \item Ver gráficos de monitoreo en tiempo real (Grafana)
\end{itemize}

\section{Backend — \texttt{backend/server.js}}

Es el archivo más importante del proyecto (1153 líneas). Contiene toda la lógica del servidor.

\subsection{Funciones Principales}

\subsubsection{Autenticación}
\begin{itemize}
    \item \texttt{POST /api/send-code}: Envía código de verificación al email
    \item \texttt{POST /api/register}: Registra nuevo usuario (nombre, email, contraseña hasheada con bcrypt)
    \item \texttt{POST /api/login}: Verifica credenciales e inicia sesión
    \item \texttt{POST /api/forgot-password}: Envía código de 6 dígitos al email
    \item \texttt{POST /api/verify-reset-code}: Verifica el código de recuperación
    \item \texttt{POST /api/reset-password}: Restablece la contraseña
\end{itemize}

\subsubsection{Trading}
\begin{itemize}
    \item \texttt{GET /api/precios}: Obtiene precios actualizados de criptomonedas
    \item \texttt{POST /api/trade}: Ejecuta compra/venta (verifica saldo, actualiza portafolio)
    \item \texttt{GET /api/usuario/:id/portafolio}: Obtiene las tenencias del usuario
    \item \texttt{GET /api/user/:id/transaction-history}: Historial de transacciones
\end{itemize}

\subsubsection{Pagos MercadoPago}
\begin{itemize}
    \item \texttt{POST /api/payment/create}: Inicia depósito, envía código 2FA
    \item \texttt{POST /api/payment/confirm}: Confirma depósito con código email + PIN, crea pago en MP
    \item \texttt{POST /api/payment/webhook}: Webhook de MercadoPago (confirmación en tiempo real)
    \item \texttt{POST /api/withdraw}: Solicita retiro a cuenta bancaria colombiana
    \item \texttt{POST /api/withdraw/confirm}: Confirma retiro con 2FA
    \item \texttt{GET /api/user/:id/mercadopago-history}: Historial de pagos MP
    \item \texttt{GET /api/user/:id/financial-summary}: Resumen financiero del usuario
\end{itemize}

\subsubsection{Seguridad y Auditoría}
\begin{itemize}
    \item \texttt{POST /api/user/:id/set-pin}: Configura PIN de seguridad (6 dígitos)
    \item \texttt{POST /api/user/:id/verify-pin}: Verifica PIN
    \item \texttt{GET /api/usuario/:id/access-log}: Registro de accesos
    \item \texttt{GET /api/usuario/:id/trade-audit}: Auditoría de operaciones
    \item \texttt{GET /api/usuario/:id/balance-history}: Historial de saldo
\end{itemize}

\subsubsection{Monitoreo}
\begin{itemize}
    \item \texttt{GET /metrics}: Expone métricas en formato Prometheus (CPU, memoria, duración de requests, cantidad de requests)
\end{itemize}

\subsection{Seguridad Implementada}

\begin{itemize}
    \item \textbf{2FA}: Doble verificación para depósitos y retiros (código email + PIN de 6 dígitos)
    \item \textbf{AES-256-CBC}: Cifrado de todos los montos sensibles antes de almacenarlos en DB
    \item \textbf{bcrypt}: Hash de contraseñas con salt
    \item \textbf{Rate Limiting}: Límite de 100 requests global cada 15 minutos, 10 intentos de auth
    \item \textbf{Helmet}: Headers de seguridad HTTP (CSP, X-Frame-Options, etc.)
    \item \textbf{CORS restringido}: Solo orígenes configurados en ALLOWED\_ORIGINS
    \item \textbf{XSS Sanitization}: Limpieza de inputs con sanitizeHtml
    \item \textbf{express-validator}: Validación de todos los endpoints
    \item \textbf{SQL Injection prevention}: Parámetros parametrizados en todas las queries
\end{itemize}

\subsection{Ejemplo de Flujo de un Depósito}

\begin{enumerate}
    \item Usuario ingresa monto en COP en la billetera
    \item Frontend llama a \texttt{POST /api/payment/create}
    \item Backend envía código de verificación al email del usuario
    \item Usuario ingresa el código + su PIN de seguridad
    \item Frontend llama a \texttt{POST /api/payment/confirm}
    \item Backend verifica código y PIN, crea preferencia en MercadoPago
    \item MercadoPago redirige al usuario al portal de pago (PSE, Efecty, etc.)
    \item Al completarse, MercadoPago notifica via webhook
    \item Backend actualiza el saldo del usuario y registra en \texttt{mercadopago\_payments}
\end{enumerate}

\section{\texttt{backend/tracing.js} — OpenTelemetry}

Se ejecuta al iniciar el backend. Configura el SDK de OpenTelemetry para:

\begin{itemize}
    \item \textbf{Instrumentar HTTP}: Captura todas las peticiones entrantes y salientes
    \item \textbf{Instrumentar Express}: Crea spans para cada ruta del backend
    \item \textbf{Instrumentar PostgreSQL}: Captura queries a la base de datos
    \item \textbf{Exportar a Tempo}: Envía las trazas via OTLP HTTP a \texttt{tempo:4318/v1/traces}
\end{itemize}

\begin{lstlisting}[language=JavaScript, caption=tracing.js simplificado]
const sdk = new NodeSDK({
    traceExporter: new OTLPTraceExporter({
        url: 'http://tempo:4318/v1/traces'
    }),
    instrumentations: [
        new HttpInstrumentation(),
        new ExpressInstrumentation(),
        new PgInstrumentation()
    ]
});
sdk.start();
\end{lstlisting}

\subsection{Loki (\texttt{loki-config.yaml})}

\textbf{Qué hace}: Almacena logs (registros de texto) de todos los contenedores. Permite consultar con lenguaje LogQL.

\textbf{Ejemplo de consulta en Grafana}:
\begin{lstlisting}
{container="advance-trading-backend-1"} |= "error"

\end{lstlisting}

\textbf{Configuración}: Usa el motor de índices TSDB con esquema v13 y almacenamiento local en disco.

\subsection{Promtail (\texttt{promtail-config.yaml})}

\textbf{Qué hace}: Es el recolector. Lee los logs de los contenedores Docker y los envía a Loki. También puede leer archivos de log del sistema.

\subsection{Prometheus (\texttt{prometheus-config.yaml})}

\textbf{Qué hace}: Almacena métricas numéricas (rendimiento). Cada 15 segundos consulta al backend en \texttt{/metrics}.

\textbf{Ejemplos de métricas disponibles}:
\begin{itemize}
    \item \texttt{http\_request\_duration\_seconds\_count}: Cantidad de requests por endpoint
    \item \texttt{http\_request\_duration\_seconds\_bucket}: Distribución de tiempos de respuesta
    \item \texttt{process\_cpu\_user\_seconds\_total}: CPU usada por el backend
    \item \texttt{nodejs\_heap\_size\_bytes}: Memoria heap de Node.js
\end{itemize}

\subsection{Tempo (\texttt{tempo-config.yaml})}

\textbf{Qué hace}: Almacena trazas distribuidas. Cada petición al backend genera una traza que muestra el tiempo de cada paso.

\textbf{Puertos}:
\begin{itemize}
    \item 3200: API HTTP de Tempo (para consultas de Grafana)
    \item 4318: Receptor OTLP HTTP (para recibir trazas del backend)
\end{itemize}

\subsection{Grafana}

Panel de control unificado. Acceso: \texttt{http://localhost:3101}, usuario: \texttt{admin}, contraseña: \texttt{advance2024}.

\textbf{Datasources preconfigurados}:
\begin{itemize}
    \item \textbf{Loki}: Para consultar logs con LogQL
    \item \textbf{Prometheus}: Para consultar métricas con PromQL
    \item \textbf{Tempo}: Para buscar y visualizar trazas distribuidas
\end{itemize}

\section{Seguridad}

\subsection{Encriptación AES-256}

Todos los montos financieros se almacenan cifrados en la base de datos usando AES-256-CBC:

\begin{itemize}
    \item \textbf{Clave}: 64 caracteres hexadecimales (32 bytes), almacenada en \texttt{ENCRYPTION\_KEY}
    \item \textbf{IV}: Vector de inicialización único por cada valor cifrado
    \item \textbf{Columnas encriptadas}: \texttt{amount\_encrypted}, \texttt{precio\_encrypted}, \texttt{saldo\_encrypted}, etc.
    \item Las columnas en texto plano se mantienen para consultas, las encriptadas para auditoría
\end{itemize}

\subsection{Autenticación de Doble Factor (2FA)}

Para operaciones sensibles (depósitos y retiros):
\begin{enumerate}
    \item El usuario solicita la operación
    \item El backend envía un código de 6 dígitos al email del usuario (expira en 10 minutos)
    \item El usuario ingresa el código
    \item El usuario ingresa su PIN de seguridad (configurado previamente en Ajustes)
    \item Solo después de verificar ambos, se ejecuta la operación
\end{enumerate}

\section{Script de Prueba — \texttt{generate-traffic.sh}}

Script Bash que genera tráfico de prueba para verificar el monitoreo:

\begin{itemize}
    \item Consulta precios 15 veces
    \item Intenta login con credenciales incorrectas (3 veces)
    \item Consulta endpoints de historial, portafolio, resumen financiero
    \item Genera 20 requests aleatorios a distintos endpoints
\end{itemize}

\section{Guía de Uso}

\subsection{Inicio Rápido}

\begin{enumerate}
    \item Crear archivo \texttt{.env} en la raíz con las variables SMTP, ENCRYPTION\_KEY y tokens MP
    \item Ejecutar \texttt{docker compose up -d --build}
    \item Abrir \texttt{http://localhost:3000}
    \item Crear una cuenta
    \item Explorar el dashboard, depositar, operar, retirar
    \item Abrir \texttt{http://localhost:3101} (admin / advance2024) para ver monitoreo
\end{enumerate}
